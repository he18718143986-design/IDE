# 卡文案规范

> **范围**：只规范给非技术用户当场点选的三类卡——冲突卡、意外卡、线上卡——的文案。本文件是文案规范，不改产品界面，不宣称条目级高亮已交付，也不把 J.32 或 J.22 子卡写成已完成。
>
> **谁能改**：走任务卡修订。机器可校验的块（术语黑名单、三类卡的选项表）改了必须能通过 `npm run check:docs`。

## 是否真懂不是门禁

<!-- j33-understanding-not-a-gate -->

用户是否真懂，只能靠非技术用户试用验证，不是门禁，不得做成 can_merge 派生输入或退出码门禁。

文档门禁只检查本规范的格式与用词来源：黑名单是否只用 [术语表](../glossary.md) 已收录词，每个选项是否都有非空的「推荐项」和「后果一句话」，以及上面这句声明是否还在。门禁不能、也不会替用户判断「看懂了没有」。

## 术语黑名单

这三类卡是给非技术用户当场点选的。黑名单只收录 [`glossary.md`](../glossary.md) 已经写进术语表、但写进选项或「后果一句话」会把用户拽进内部实现的词。未收录词不得进入本名单，避免另做一份无人维护的私词表。

本名单是有理由的子集，不是术语表的全文拷贝。不把用户在旅程里本来就会看到的词放进来，以免规范和已有白话互相打架：

- 不收录「[密封](../glossary.md#密封)」「[合同](../glossary.md#合同)」「[试玩](../glossary.md#试玩)」「[卡片流](../glossary.md#卡片流)」：它们在术语表里就是给用户看的，线上卡现有文案也会说到「修复合同」。
- 收录「[PAB](../glossary.md#PAB)」「[DesignNote](../glossary.md#DesignNote)」「[EvidenceBundle](../glossary.md#EvidenceBundle)」「[Daemon](../glossary.md#Daemon)」「[任务卡](../glossary.md#任务卡)」「[北极星场景](../glossary.md#北极星场景)」「[挂账](../glossary.md#挂账)」「[墓地](../glossary.md#墓地)」：这些是内部产物、管家进程或施工台账用词；「北极星场景」当前做不到，不能写进选项里让人误以为已经交付。

下面这个 YAML 块是机器校验的唯一名单来源。每一项必须能在术语表的 `##` 标题或 `<a id>` 锚点里对上（含 `PAB` / `pab`、`DesignNote` / `designnote` 这类别名）。

```yaml card-copy-blacklist
terms:
  - PAB
  - DesignNote
  - EvidenceBundle
  - Daemon
  - 任务卡
  - 北极星场景
  - 挂账
  - 墓地
```

## 选项必须有「推荐项」和「后果一句话」

每一类卡的每一个选项，都必须同时具备两个非空字段：

- **推荐项**：建议写在选项上、让用户直接点选的那句白话。
- **后果一句话**：选了之后会发生什么，用一句人话写清，不写内部实现细节。

当前产品界面往往只展示选项标签；本规范规定的是文案结构，不表示界面已经按这两列展示，也不在本文件里改产品代码。以后若新增选项，必须先在对应的选项块里补上这两个字段。

下面三类选项块按卡种分开，均以 `yaml card-copy-options` 围栏供机器读取。选项用词尽量对齐现有产品或规格里已经出现的说法。

### 冲突卡

方案审阅页里「需要你抉择的冲突」。下列推荐项对齐现有方案草案里会生成的冲突选项（先跑通还是一次到位、这一版做全部还是先做一部分）。后果一句话按该选项的字面含义写清取舍，不新增产品行为。

```yaml card-copy-options
card_type: 冲突卡
options:
  - 推荐项: 先跑通主流程，界面以后再说
    后果一句话: 这一版先把能走通的主流程做出来，界面和文案先放下，以后再打磨。
  - 推荐项: 界面和文案也要一次到位
    后果一句话: 这一版会同时做主流程和界面文案，可能要更久才能看到能用的结果。
  - 推荐项: 这一版尽量都做（假数据演示）
    后果一句话: 这一版会按现在列出的模块尽量都做，可以用假数据先演示。
  - 推荐项: 先做进度+预警，财务与报表下一期
    后果一句话: 这一版只做进度和预警；财务与报表放到下一期再做。
```

### 意外卡

目前已经交给用户点选的，是设计步骤「需要装新库」那张意外卡（可以 / 不行 / 稍后处理）。推荐项和后果一句话对齐这张卡上的按钮与说明，不改其既有行为。

规格里还写过「技术方案没理顺」时的「我再想一次 / 先停下」，以及五类要用户点头的升级决策。那些若尚未做成带选项的独立界面，本文件不为它们编造新按钮，也不宣称已经交付；一旦做成选项卡，必须按本结构补上「推荐项」和「后果一句话」。

```yaml card-copy-options
card_type: 意外卡
options:
  - 推荐项: 可以（加依赖）
    后果一句话: 会中止这份工作、在计划里加上要装新库的步骤并等你重新确认；不会悄悄改已经确认过的内容。
  - 推荐项: 不行
    后果一句话: 会中止这次安排，并且不装这个新库。
  - 推荐项: 稍后处理
    后果一句话: 先把这张卡收起来，这次既不装库也不中止；之后还要再做决定。
```

### 线上卡

画布上「某某停了」那张线上卡。目前交给用户点的主选项是「让 AI 看看」。本块只为这一项写结构化字段，不编造尚未提供的按钮，也不宣称运维已经闭环。

```yaml card-copy-options
card_type: 线上卡
options:
  - 推荐项: 让 AI 看看
    后果一句话: 系统会根据这次停止时的错误生成一份修复合同，不会改已经合入的内容。
```
