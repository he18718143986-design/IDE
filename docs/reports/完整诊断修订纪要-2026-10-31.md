## 0. 缘起

对 `docs/` 做了两套独立挑剔诊断（产品意图反查 + 独立交付可行性），结论同向：

1. **交付语义根因**：中栏所见与合同所签可以脱节（ADR-0018 已立；本轮加固白话与接线口径）。
2. **体验铁硬**：按钮文案打架、D3/D9 撕裂、Canvas 语义横跳、编译抖动、决议/墓地审讯感、Mermaid 不可读、拒码当人话、质询台逼用户当法官。

本纪要把「完整诊断 A+B」收成 **14 条定型**，并最小补丁落盘。

## 1. 十四条定型（必须可对用户复述）

| # | 定型 | 落点 |
| :--- | :--- | :--- |
| 1 | **中栏确认的范围 = Worker 拿到的范围**；禁聊天直推 / `buildL0Plan(chat)` | ADR-0018 §0；supervisor §15.3 / §15.5 |

## 2.1 审阅修补（Tina · PR #2 · 合入前）

针对审阅三点闭环（审阅范围仅 `docs/`）：

1. **高 · 规划 vs 开工**：废除「一律确认开工」过强口径。需 PAB/Plan 时第一次主按钮定为 **「确认方案，开始规划」**（批准=冻结+启动规划）；合同级才是 **「确认开工」**。tiny 仍一次到位。权威落点见 supervisor §3.2 / §5.2.1 / §16.3、ADR-0018 UI 文案定型、delivery-lifecycle §4。
2. **高 · JourneyStage**：§16.2 新增 **「方案 · 整理项目地图」** / `PROJECT_MAPPING`（进入/退出条件、右栏可聊、与 `GRAPH_MAPPING` 交接锁区分）；J-01 / D8 同步。
3. **低 · 纪要**：删除对不存在的 `MANIFEST.md` 的指向；改动清单内嵌本节；并清理 blockquote 尾随空格写法。
