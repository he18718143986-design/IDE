## 六件可反哺机制

三栏：目标态条款 / 现行落点 / 处置。六件都不改合同单位，也不把「每份合同一次合入」改成方案级自动合入。

| # | 目标态条款 | 现行落点 | 处置 |
| :--- | :--- | :--- | :--- |
| 1 | `machine_auto`：机器生成不得冒充用户输入（§0） | 条目来源没有机器态；工序结论写在证据与 `can_merge` | **可反哺**：给机器产物单独标记。不替换 `user_edited` |
| 2 | `halt.md` 四字段：现象 / 已试方案 / 需要什么决策 / 阻塞范围（§6） | 设计升级与验证失败走 `PENDING_RESUME`，原因在 `.stagent/records/<id>/suspension.json`；意外卡是三段式 | **可反哺**：停工记录对齐这四字段。不新增用户项目根目录的 `halt.md` |
| 3 | 合入存证：谁、何时、关联 gate 结论、方案包版本哈希（§5，S-2） | 合入是每份合同一次点击；证据包带退出码。没有「方案包版本哈希 + 授权人」这一组字段 | **可反哺**：在现有合入记录上补这四项。patch 自动合入主线仍是冲突项，见下表 |
| 4 | 带 `rl` 的确认必须 `mode: single`，否则无效并回落 `ai_inferred`（§11，R15/R23） | 重确认档可以逐项勾选；没有 `rl` 字段，也没有「批量则确认作废」 | **可反哺**：先定无效与回落规则。RL-1～RL-5 清单终稿写明待 Q-6 补全，不在本项里发明新红线 |
| 5 | `advisor_ref`：确认记录留下当时的 AI 建议版本（§11，Q-15） | 快照 digest 含 `frozen_quotes`、`item_quote_backlinks`、`trust_tier`。呈现日志在 `.stagent/records/surface-log`，`plain_text_version` 不进 digest | **可反哺**：把确认前展示的白话正文哈希写入同一份快照并计入 digest。不新增顾问 Agent，右栏仍不设系统提示 |
| 6 | INC-n：误分类、误放行、转述失真要登记（§6，R19） | 设计步骤漏标升级时已有 `escalation_missed`。没有独立的事故登记与披露记录 | **可反哺**：漏标与转述失真落一条事故记录（合同、条款、时间、是否已停）。全套「回滚 → 披露 → 追认」仍待 J.41b 单独立项 |
