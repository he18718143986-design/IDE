# 业主确认与试玩操作规程

> **地位**：面向非技术业主的分步操作清单（TASK-J.34）。规格条款仍以 [`supervisor.md`](../specs/supervisor.md)「密封前原话回链」与 [`playtest-self-check.md`](../specs/playtest-self-check.md) 为准；本页只写「你按什么顺序点、看什么算过」。
> **谁能改**：走任务卡修订；不改产品代码；不另造与规格冲突的信任档定义。
> **旅程入口**：[`user-journey.md`](../user-journey.md) 的 S2→Seal 与 S6。

---

## 1. 对照面怎么看

签字前，中栏应能让你对照「自己说过的事」和「方案里记下的项」。

1. 打开方案页，找到对照相关区块（有时叫「说过的每件事都有着落」一类提示）。
2. 逐项看：有原话对着落的项，和标成未覆盖 / 对不上的项。
3. **通过**：对不上的项被明确标出，没有被悄悄跳过。
4. **失败**：对不上的项却被当成已经覆盖，或对照区整块不见。

权威口径见 [`playtest-self-check.md`](../specs/playtest-self-check.md) §0.1 第 2 步，以及术语[`对照面`](../glossary.md#对照面)。

---

## 2. 三档怎么选（[`信任档`](../glossary.md#信任档)）

确认前你会选一档「这次确认有多严」。三档含义（与规格一致，不另造定义）：

| 档 | 你通常会看到 | 你要注意 |
| :--- | :--- | :--- |
| **标准**（默认） | 默认出示对照面 | 先看完对照，再点确认 |
| **重确认** | 对照面 + 逐项勾选 | 未勾完时确认按钮应不可点；勾完才能确认 |
| **轻确认** | 可以不把对照面当作默认确认步骤 | **机械回链不降级**：系统仍按已登记原话核对；伪造或哈希对不上仍会失败 |

选档不等于「可以跳过回链」。轻确认只影响你是否必须先看完对照面 UI，不降低核对标准。

---

## 3. 确认密封按键顺序

1. 看完方案与对照（标准档 / 重确认档按上一节）。
2. 选好信任档。
3. 确认眼前方案就是你要的。
4. 点主按钮：需要先规划时多为「确认方案，开始规划」；很小、只有一份工作时可能是「确认开工」。
5. 这一步叫做[`密封`](../glossary.md#密封)：方案冻成快照，后面不能悄悄改。

**你不需要**：把「开始规划」当成已经允许改代码；用一次「确认开工」冒充后面好几份合同的授权。

---

## 4. 试玩判分与证据表用法

施工并过完硬性检查后，请你[`试玩`](../glossary.md#试玩)。

1. 打开 [`playtest-self-check.md`](../specs/playtest-self-check.md) §0.1 判分表，按第 1～9 步逐项判定（看到 X 即通过 / 看到 Y 即失败）。
2. 亲自在真实预览里点一点、看一看；系统可以引导，**不能替你宣布「我满意了」**。
3. 满意后再点「合入」。
4. 在文末「试玩证据」表留**完整一行**（缺字段或只口头说「过了」算失败）。

本版**不**实现验收条目的自动点亮（§3.3）。若看到系统自己把条目点亮成已通过，按判分表第 8 步记失败并挂账，不在本规程里改产品。

## 5. 标准边界（何为未交付）

下列**当前做不到**，本规程不得写成已交付：

- [`北极星场景`](../glossary.md#北极星场景)（`scheme.md` goal-2）
- 「无人值守连续三张真实任务卡」
- 验收条目的 §3.3 自动点亮
- 商业冷静期 / ChangeOrder（另立，不在本规程）

若某段说明与本页或 `scheme.md`「当前做不到」冲突，以「未交付」为准。

---

## 6. 修卡触发

出现下列情况时**停工并修卡 / 挂账**，不要在本规程里「圆过去」：

1. 对照面或信任档行为与 [`supervisor.md`](../specs/supervisor.md)「密封前原话回链」或 J.32a/b 已交付硬约束冲突。
2. 要把本规程改成改产品代码，或扩到 `daemon/` / `src/`。
3. 要把 SOP 主文件改到卡面 `writable_paths` 以外的路径（例如另起 `docs/specs/agent-operating-procedure.md`）——须先修卡。
4. 发现自动点亮、或把未交付能力写成已交付。

相关卡：`TASK-J.34`（本规程）；信任档规格缝见 [`trust-tier-spec-boundary-brief.md`](../ledger/trust-tier-spec-boundary-brief.md)（只划界，规格卡另授权）。
