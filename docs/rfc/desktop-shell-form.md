## 1. 主题

**用户痛点（卡内已写）**：浏览器无法弹出系统级「选任意本地文件夹」；`TASK-D.1c` 只有最近列表；首次打开仍依赖终端 / 粘贴路径，期望接近 Cursor Open / Import 的同壳体验。

**本 RFC 只回答**：未来若激活 `TASK-D.1e`，产品应以哪种**桌面形态**承载「真·选文件夹 + Import/New 与工作台同壳」，以及拍板前必须钉死的边界。**不回答**具体 API、打包流水线或排期开工日。

```text
现状（已完成，勿回退）
  D.1  → loopback + #token= + AUTH + Origin
  D.1b → Daemon 托管控制台单窗口
  D.1c → 最近项目一键重开（无任意路径选夹）
  D.1d → 同源静态壳可聊（生产可用单窗口）
  C.8c → 粘贴绝对路径自救（明确不抢 D.1e）

本 RFC（讨论）
  桌面形态候选 → Tina 拍板 →（另卡）DoR 重写 → Tina 单卡授权 → 才可施工 D.1e

D.1e 状态全程维持 [DEFERRED → v0.2+]，直到 Tina 另开流水改状态
```

### 3.1 卡内已钉死的目标（实施轮才测；本 RFC 不扩写）

摘自 active `TASK-D.1e`（不改原文权威）：

1. **真·选文件夹**：产品 UI 内触发系统文件夹选择器（或受控本机助手）→ 选中路径 → 进入工作台。
2. **同壳**：Import / New / 最近 / 工作台在同一产品表面。
3. **鉴权与 Demo 不回退**：仍经 D.1（loopback、`#token=` / 安全等价注入、AUTH、Origin）；Demo 仍独立 Origin；日志无 Token 明文。

### 3.2 卡内明确不包含（本 RFC 继承，禁止偷换）

- 在未做桌面能力的纯浏览器里假装已支持任意路径选择器并标完成
- 推翻 D.1 鉴权或把 Token 长期写入可分享的 query / localStorage 明文
- 将 Demo 改为 Daemon 同源

## 4. 目标 / 非目标（本讨论稿）

### 4.1 目标

- 给出可供 Tina 比较的**候选形态表**（来自卡正文与历史口径已点名的 Electron / Tauri / 本机助手，**不发明第四条未出现过的产品路线**）。
- 写清与 **ADR-0018 Seal**、**Supervisor**、**D.1 鉴权**、**ADR-008 Demo 隔离** 的硬边界：壳只解决「怎么进工作台」，不改「进了之后怎么密封 / 怎么施工」。
- 列出必须由 Tina 拍板的开放问题；拍板前 **D.1e 维持 DEFERRED**。

### 4.2 非目标

- **不实现** D.1e（无 Electron/Tauri/助手代码、无打包、无签名、无自动更新）。
- **不**把 D.1e 改成 READY / NEW_TASK / 可开工。
- **不**选定「唯一正确」形态并据此写死 writable_paths 或施工卡。
- **不**复活 / 激活 `TASK-S.3`（D-5 已拍不激活）。
- **不**销 OP-34；**不**宣称端到端闭环或「已接近 Cursor」。
- **不**改 Demo Origin、不扩 Supervisor 广播面、不旁路 ADR-0018 密封缝。

## 5. 候选形态对比（整理已知选项 · 未选定）

卡正文与矩阵口径已点名三类：「系统文件夹选择器 / 轻量本机助手或 Electron·Tauri」。下表只做对比，**推荐列留空给 Tina**。

| 维度 | A. 轻量本机助手 | B. Electron 壳 | C. Tauri 壳 |
| :--- | :--- | :--- | :--- |
| **一句话** | 小助手调系统选夹 + 启动/复用 Daemon，工作台仍主要是浏览器表面 | 用 Electron 包一层，选夹与工作台同窗 | 用 Tauri 包一层，选夹与工作台同窗 |
| **「同壳」程度** | 偏弱～中：助手 + 浏览器；需产品文案说清「算同一产品」 | 强：单一桌面应用表面 | 强：单一桌面应用表面 |
| **真·选文件夹** | 系统对话框（助手进程） | `dialog.showOpenDialog` 类 | 原生对话框 / 插件 |
| **与现网 D.1b–d 关系** | 改动面相对小；继续复用 Daemon 托管控制台 + `#token=` | 需定义壳如何加载现有 Studio；鉴权注入须等价 D.1 | 同左 |
| **打包 / 签名 / 更新** | 助手体积小；仍要分发与信任链 | 体量大；签名、自动更新、多平台矩阵成本高 | 体积通常小于 Electron；Rust/工具链与签名成本仍在 |
| **安全注意力** | 助手权限边界、如何把路径交给 Daemon、Token 仍禁明文落盘 | 壳内 webview / 本地文件桥；禁止把 Token 塞进可分享存储 | 同左；另需钉死与 Daemon 的 IPC 信任边界 |
| **工程体量（相对）** | 相对最小（仍不是「小修」） | 大 | 中～大 |
| **已知出处** | D.1e 卡「本机助手」；D.1c 残余口径 | D.1e 卡 / 矩阵「Electron·Tauri」 | 同左 |
| **主要风险** | 「同壳」用户心智是否够；助手与浏览器双表面 | 打包与维护长期成本；易膨胀成「重写壳」 | 团队熟悉度 / 生态；同样要防壳膨胀 |

> **诚实声明**：上表**不是**选型结论。任选其一进入激活前，仍须 DoR 重写把「同壳定义、鉴权注入、失败态、平台矩阵」写成可测断言。

### 5.1 明确不作为本 RFC 候选的路线

| 路线 | 为何不列作候选 |
| :--- | :--- |
| 纯浏览器 File System Access API 冒充「真·选文件夹」 | 卡明文：浏览器无法满足「选任意本地文件夹」产品期望；且「未做桌面能力却标完成」为 FAIL |
| 削弱 D.1 / 把 Demo 改同源换取同壳 | 推翻 ADR-008 / D.1；卡与架构 §11 注 8 禁止 |
| 终端说明书替代选夹 | 与「同壳」目标相反；C.8c 已提供粘贴路径自救，**不**算 D.1e |

## 6. 与 ADR-0018 Seal / Supervisor / 鉴权边界

桌面形态解决的是 **「如何进入已鉴权工作台」**，不是 **「进入后如何密封方案与派工」**。下列边界本 RFC **固定继承**，不开放为「可用壳绕过」的拍板项：

| 边界 | 权威 | 对桌面壳的含义 |
| :--- | :--- | :--- |
| **D.1 鉴权** | D.1 完成口径；loopback、`#token=` / 安全等价注入、首帧 AUTH、Origin/Host | 选夹成功后进入工作台的通道必须仍满足 D.1；禁止 Token 进 query / localStorage 明文；日志无 Token 明文 |
| **Demo 独立 Origin** | ADR-008；架构 §11 注 8 | 控制台可与 Daemon 同源托管；**Demo 预览必须独立 Origin**；壳不得把 Demo 改成 Daemon 同源 |
| **Intent → Executable Seal** | ADR-0018 | 壳不得提供「跳过中栏确认、用聊天直推 Scope / 直接派工」的旁路；密封与「确认开工」仍是唯一真相缝 |
| **Supervisor 分权** | supervisor 规格；ADR-0007 / 0014 | 壳不扩大 Supervisor 广播面；**不**借本 RFC 激活 S.3；建议流 / HUD 帧仍按 D-5 维持 DEFERRED |
| **合同为交付单元** | ADR-0015；delivery-lifecycle | 选夹 / Import 只绑定工作区与会话钥匙，**不**自动等于签合同或开工 |
